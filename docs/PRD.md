# TuneBridge 音桥 · 产品需求文档（PRD）

> 2026 Qoder 高校创造力大赛 · LifeHack 生活娱乐赛道
> 版本：v1.1（MVP + 账号与历史）｜更新日期：2026-11-19

## 1. 一句话介绍

**TuneBridge 音桥**是一个浏览器里打开就能用的歌单搬运工具：登录本站音桥账号、在目标平台完成授权后，粘贴另一平台歌单链接，系统自动逐首搜索与匹配，由你勾选确认后写入目标平台，并把这份报告存进迁移历史。

## 2. 背景与问题

### 2.1 真实场景

- 小 A 一直是 QQ 音乐用户，最近买了 AirPods / HomePod，想转用 Apple Music，但 20 个自建歌单、上千首歌没有精力手动重建。
- 小 B 被 Apple Music 的编辑推荐吸引，却舍不得 QQ 音乐里多年积累的华语歌单，两个平台来回切换。
- 跨区、换手机、会员到期、朋友分享歌单……每一次平台迁移，都是一次重复劳动。

### 2.2 现有方案的问题

| 现有方式 | 问题 |
| --- | --- |
| 手动逐首搜索添加 | 一首歌约 20–30 秒，100 首歌要 40 分钟以上 |
| 截图 / 文本清单 | 只能「看」，不能恢复为可播放歌单 |
| 第三方爬虫脚本 | 要装环境、改代码，普通用户无法使用 |
| 平台官方迁移工具 | 只覆盖部分平台，且几乎不跨生态 |

### 2.3 机会

QQ 音乐与 Apple Music 分别代表国内曲库与全球生态，用户重叠度高、迁移诉求强，但两者之间没有官方互通工具。一个**无需安装、在浏览器完成授权、自动匹配、给出迁移报告**的小工具，可以实打实解决一个高频又烦人的问题。

## 3. 目标用户

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| 双平台学生党 | 手机 QQ 音乐、平板/电脑 Apple Music | 把歌单低成本搬过去 |
| 换生态用户 | 新购 iPhone / Mac / HomePod | 保留多年收藏 |
| 歌单创作者 | 在两个平台同步运营歌单 | 一次编辑、两边同步 |
| 好奇体验者 | 比赛评委、朋友 | 不登录也能 30 秒看到完整效果 |

## 4. 产品目标与非目标

### 4.1 MVP 目标

1. 用户可以在浏览器中完成歌单迁移：真实账号可用 **Apple Music → QQ 音乐**（迁出自己的资料库，无需 Apple 开发者账号）与 **QQ 音乐 → 网易云音乐**；**QQ 音乐 ↔ Apple Music** 双向在演示模式可用，迁入 Apple 需要 Apple 开发者账号，默认停用。
2. 目标平台授权流程清晰，来源歌单链接粘贴后能立即预览。
3. 自动匹配歌曲，**由用户勾选确认后才创建目标歌单并写入**，输出成功 / 未匹配 / 已跳过的逐首结果。
4. 无平台账号、无开发者凭据的用户可以通过**演示模式**完整体验整个流程（只需注册一个本站音桥账号）。
5. 全流程不持久化任何音乐平台凭据，服务端不记录 Cookie / Token；落盘的只有音桥账号与迁移报告快照。
6. 迁移结果与历史可以在服务重启后查看，但历史只读，绝不自动继续或重试写入。

### 4.2 非目标（本期不做）

- 不迁移「我喜欢」、专辑、本地文件、播放记录。
- 不做歌单持续双向同步（仅一次性复制）。
- 不做音频下载、播放、版权绕过。
- 不覆盖 Spotify 等更多平台（网易云已作为目标平台接入，支持扫码登录真实账号；架构继续预留更多平台）。
- 不做后台管理、运营面板、找回密码、邮件验证与多实例共享会话。
- 不做跨设备同步或云端账号（音桥账号只存在于部署实例本地的 H2 文件中）。
- 不做自动断点续传与自动重试：写入结果不确定时一律交给人工核查。

## 5. 核心用户流程

```
注册 / 登录音桥账号（本站账号，不是音乐平台账号）
   ↓
选择方向 A → B
   ↓
授权登录目标平台 B（QQ Cookie 连接 / 网易云 App 扫码 / 演示账号）
   ↓
粘贴来源平台 A 的歌单分享链接
   ↓
解析并预览歌单（封面、名称、曲目数、前几首）
   ↓
点击「开始匹配」→ 读取 A 歌单 → 逐首在 B 搜索匹配（此时不写入任何平台）
   ↓
审阅逐首结果，勾选要带走的歌曲 → 点击「确认迁移」
   ↓
创建 B 歌单 → 按来源顺序批量写入所选歌曲
   ↓
迁移报告：成功 N 首 / 未匹配 M 首 / 已跳过 K 首 / 目标歌单入口（报告存入迁移历史）
```

**备份与恢复闭环**：在「歌单备份」区读取 QQ 链接、手动粘贴或导入 CSV / JSON 得到预览曲目后，可直接选择任一已连接平台作为目标点「开始恢复迁移」。这条路径不需要来源平台连接，预览曲目就是迁移来源，之后的逐首匹配、勾选确认、写入与报告和主流程完全一致，同样存入迁移历史；单次只提交预览中的前 `max-tracks` 首（默认 200），超出部分明确提示且不提交。

**多歌单批量迁移**：在「批量迁移」区选定方向后，可以「读取我的歌单」列出来源账号的歌单并勾选，也可以一次粘贴多条歌单链接（单次最多 10 份，重复链接自动忽略）。队列由浏览器排队，一次只提交一份给服务端，仍然走上面同一条「匹配 → 审阅勾选 → 确认写入」流程，每份都单独生成一份可核对的报告并存入迁移历史。用户可以对队列里的某一份选择「暂不迁移」（跳过）或「重新排队」，全部处理完后可导出批次小结 CSV；产品不会因为排队而自动连续写入任何平台。

### 5.1 关键交互原则

- **三步之内开始**：方向、授权、链接，主按钮始终只有一个。
- **每一步都有反馈**：连接状态、解析 loading、迁移进度、逐首结果。
- **匹配与写入分离**：匹配阶段只读；只有明确勾选确认才会创建歌单和写入，未确认的预览过期后自动失效。
- **失败可解释**：Apple 网页版令牌取不到、`media-user-token` 过期、Cookie 失效、QQ 写接口受限，都给出人话提示与替代方案。
- **结果不确定时不重试**：写入中断或任务在写入阶段被重启，报告标注「结果待核查」，引导用户去目标平台确认，产品绝不自动重试。
- **演示优先**：评委只需注册一个音桥账号，即可一键进入演示并跑通双向迁移。

## 6. 功能需求

### 6.1 P0（MVP 必须）

| 编号 | 功能 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| F1 | 平台方向切换 | QQ ↔ Apple 双向切换（演示模式），真实账号可用 Apple → QQ 与 QQ → 网易云，可一键交换 | 切换后授权区、链接示例、提示文案同步更新；不可用的方向给出说明 |
| F2 | 演示授权 | 无需凭据连接演示账号，使用内置曲库 | 点击即连接，状态变为「演示模式」 |
| F3 | QQ 真实连接 | 粘贴 y.qq.com Cookie，服务端解析 uin 与票据 | 连接成功后显示脱敏账号；无效 Cookie 返回明确错误 |
| F4 | Apple 真实连接 | 粘贴 music.apple.com 的 `media-user-token` 即连接；服务端自行取用 Apple 网页版的访问令牌读取资料库，无需 Apple 开发者账号 | 令牌为空时被拒绝；连接成功后可列出并读取本人资料库歌单，平台名标注「仅迁出」 |
| F5 | 歌单链接解析 | 支持 QQ 歌单链接/ID、Apple 歌单链接/ID、演示链接 | 非法链接被拒绝且提示格式 |
| F6 | 歌单预览 | 展示封面、名称、作者、曲目数与曲目列表 | 预览数据与实际迁移读取一致 |
| F7 | 自动迁移 | 后台任务读取、匹配、创建、写入，前端轮询进度 | 两个方向均可完成；进度与日志实时更新 |
| F8 | 匹配报告 | 逐首展示匹配结果、目标歌曲、相似度、未匹配原因 | 报告可滚动查看，统计数字准确 |
| F9 | 演示音乐库 | 演示模式下展示本次会话创建的歌单，可再次作为来源 | 迁移完成后可在目标演示库中看到新歌单 |
| F10 | 会话级凭据 | 凭据仅存于服务端会话内存，断开连接即清除 | 重启服务或断开连接后不可用；日志无明文凭据 |
| F11 | 歌单备份与恢复 | 读取 QQ 歌单、粘贴曲目或导入 CSV/JSON，在浏览器预览并导出；也可选择已连接平台，把预览曲目作为来源恢复成新歌单 | 预览、导出与恢复共用同一份曲目数据；恢复不要求来源平台已连接，输出逐首报告 |
| F12 | 音桥账号 | 本站账号注册 / 登录 / 退出，本机模式免邀请码，公网模式需邀请码 | 用户名规范化、弱密码与重名被拒；登录失败提示不泄露账号是否存在 |
| F13 | 账号隔离 | 连接、任务、历史归属音桥账号 | 其他账号读取返回 404；同账号其他会话只读，不能确认或放弃 |
| F14 | 任务持久化与迁移历史 | 每个状态变更保存报告快照，历史分页可查、只读 | 服务重启后历史仍在；未确认预览标记为已中断；历史中无法提交确认 |
| F15 | 部署边界 | LOCAL 只监听回环、拒绝转发头；PUBLIC 要求 TLS、Secure Cookie、规范源与邀请码 | 配置不合规直接拒绝启动；伪造 Host / 跨站写请求返回 403 |
| F16 | 请求防护 | 会话 CSRF 头、登录换会话 ID、认证限流、请求体上限 | 缺少 CSRF 返回 403；超频返回 429；超大请求体返回 413 |
| F17 | 多歌单批量迁移 | 列出来源账号歌单或粘贴多条链接排成队列，逐份复用「匹配 → 人工确认 → 写入」流程，并导出批次小结 | 单次最多 10 份且同一链接只排一次；每份仍需明确确认才写入；每份照常生成独立历史报告；方向锁定后不能中途更换 |
| F18 | 网易云目标平台 | 网易云 App 扫码登录真实账号，服务端渲染二维码并轮询确认状态，随后搜索、创建歌单并写入 | 二维码与登录会话一一绑定，约 2 分钟过期后可刷新；确认成功后凭据只留在服务端会话内存，不回传前端；本机部署还可用 CLI 配对码替代扫码 |
| F19 | Apple 仅迁出 | 用 Apple 网页版自身的访问令牌读取资料库；真实账号写入 Apple 被拦住，演示模式不受影响 | 未配置开发者令牌时迁入 Apple 返回 503 与可操作提示；网页版令牌不下发前端、不落库；Apple 改版导致取不到令牌时提示「暂时取不到…」而不是静默失败 |
| F20 | Apple 网页版令牌自举 | 服务端从 music.apple.com 前端资源中发现并缓存访问令牌，到期前自动轮换 | 取不到时返回可操作的 502 提示；令牌不下发前端；网页改版有测试兜底 |

- 多歌单批量迁移（已实现：「批量迁移」区列出来源歌单或粘贴多条链接排队，逐份确认，导出批次小结 CSV）。

## 7. 页面与信息架构

单页应用，八个区域：

1. **首屏 Hero**：品牌、价值主张、核心 CTA、能力标签。
2. **迁移工作台**：
   - 方向选择（A → B，交换按钮）；
   - 来源连接卡与目标连接卡；
   - 来源链接输入 + 解析预览；
   - 匹配按钮、勾选确认区与说明。
3. **进度浮层**：步骤时间线、进度条、实时日志、当前曲目。
4. **结果页 / 弹层**：统计卡、逐首报告、目标歌单入口、演示音乐库入口。
5. **备份与恢复**：歌单链接读取、手动粘贴、CSV/JSON 导入，预览后导出或选择目标平台恢复迁移。
6. **批量迁移**：迁移方向、来源歌单列表（读取我的歌单 + 全选）与多行链接粘贴、队列清单（每份的状态、写入数、目标歌单入口、移出队列 / 重新排队）、「迁移下一份」与批次小结导出。队列只在前端排队，一次只跑一份，逐份确认。
7. **音桥账号弹窗**：登录 / 注册切换、邀请码字段（公网模式）、当前账号摘要、退出入口。
8. **迁移历史弹层**：本账号的只读报告分页列表，可按来源平台、目标平台、任务状态与日期区间筛选并导出；进入单份报告查看逐首明细与恢复提示，并可导出该份报告的 CSV 与 JSON。

### 7.1 连接弹窗

- 演示授权（推荐给评委）：一键连接。
- 真实授权：
  - QQ：Cookie 文本框 + 获取方式说明 + 安全提示；
  - Apple：`media-user-token` 文本框 + 折叠的获取步骤（F12 → Application → Cookies），主按钮「读取我的资料库」，并提示真实账号只能迁出；「Apple Music 授权」按钮仅在服务端配置开发者令牌时可用；
  - 网易云：打开弹窗即渲染二维码，用网易云 App 扫码确认（LOCAL / PUBLIC 均可用）；LOCAL 部署另可输入本机 CLI 配对码。
- 「如何在浏览器获取 Cookie」提供折叠说明。

### 7.2 未登录与失效状态

- 介绍页、本地粘贴曲目与 CSV / JSON 导入导出无需登录即可使用。
- 平台读取、连接、演示匹配与历史需要登录；未登录触发时打开账号弹窗并提示「登录后请重新点击操作」，不会自动重放刚才的操作。
- 登录失效（401）时清空页面私有数据并提示重新登录，已开始的写入不会被撤销，引导先查历史与目标平台。

## 8. 演示模式设计

演示模式不是假按钮，而是**一套内置曲库与内存音乐库**：

- 内置 QQ 风格歌单 12 首、Apple 风格歌单 10 首，包含 1–2 首对方曲库没有的歌，用于展示未匹配。
- 迁移时真实执行匹配算法、歌单创建、批量写入与结果统计，只是数据落在内存。
- 每次迁移创建的歌单进入「演示音乐库」，可继续作为下一次迁移的来源，支持 QQ → Apple → QQ 往返。
- 演示账号连接与演示音乐库绑定音桥账号的浏览器会话，退出登录后失效；迁移报告仍会存入该账号的历史。
- 页面明确标注「演示模式」，避免用户误以为操作了真实账号。

## 9. 成功指标

| 指标 | 目标 |
| --- | --- |
| 首次访问到完成演示迁移 | ≤ 90 秒（含注册登录） |
| 演示迁移匹配率（真实曲库交集） | ≥ 80% |
| 单次迁移 30 首歌耗时 | ≤ 30 秒（演示 < 3 秒） |
| 关键流程报错率 | < 5% |
| 评委可用性 | 只需注册音桥账号，无需音乐平台凭据即可完成 |
| 服务重启后历史可读 | 100%，且不产生任何自动写入 |

## 10. 数据、隐私与合规

- **最小化**：只读取歌单公开信息与曲目元数据（歌名、歌手、专辑、时长、封面）。
- **不持久化平台凭据**：Cookie、`media-user-token`、开发者令牌，以及服务端自取的 Apple 网页版访问令牌，都不写入数据库、不写日志、不落盘、不返回前端。
- **持久化范围**：数据库只保存音桥用户名、PBKDF2 密码哈希，以及迁移报告快照（方向、曲目元数据、匹配结果、统计与日志）。网易云扫码登录得到的凭据与其他平台凭据一样只存服务端会话内存；本机 CLI 模式的登录态由 CLI 自行管理，属于本机数据。
- **账号隔离**：连接与活动任务绑定浏览器会话并归属音桥账号；历史按账号查询，跨账号读取返回 404，同账号其他会话只读。
- **透明**：真实授权页明确说明数据用途；演示模式明确标注；历史弹窗说明「只读、不保存平台凭据、重启不自动重试」。
- **合规边界**：仅用于用户本人歌单备份迁移，不提供下载、破解、绕过版权或批量抓取能力；读取 Apple 资料库用的是用户自己登录网页版后的凭据与 Apple 网页版自身的访问令牌，属非官方通道，只读不写。接口变化时降级到演示模式并提示。
- **风险提示**：QQ 音乐写接口可能触发风控或需要签名通道，产品会如实报告失败，不伪造成功。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| QQ 写歌单接口风控 / 变更 | 真实迁移失败 | 逐层校验业务码；失败给出原因；演示模式兜底；文档标注 |
| Apple 不提供免开发者账号的写入通道 | 迁入 Apple 无法真实使用 | 真实账号只做迁出；迁入 Apple 需配置开发者令牌，未配置时接口直接返回 503 与替代方案（改用 QQ / 网易云为目标，或先备份歌单），演示模式不受影响 |
| Apple 网页版通道改版 | 读取资料库失败 | 令牌从网页 bundle 自动发现、过期前轮换；解析不到时返回可操作的错误提示而非空歌单，并保留演示模式兜底 |
| 第三方 API 不稳定 | 读取超时 | 超时 + 有限重试；错误可读；不静默返回空歌单 |
| 歌曲版本差异 | 匹配错误 | 标题 + 歌手 + 专辑综合打分，展示匹配依据，低置信默认不勾选 |
| 凭据泄漏 | 账号安全 | 平台凭据仅会话内存、日志脱敏、断开即清除、PUBLIC 模式强制 HTTPS |
| 历史快照与目标平台不一致 | 用户误判迁移结果 | 报告标注写入数与「待核查」提示；历史只读、禁止重新提交 |
| 重启导致任务状态错乱 | 重复写入或误认为成功 | 状态快照持久化，启动时把未结束任务标记为已中断，不自动恢复执行 |
| 公网部署被批量注册或撞库 | 账号与资源风险 | 邀请码注册、按来源与全局窗口限流、密码长度下限、失败提示不泄露账号存在性 |
| 反向代理伪造来源 | 越权访问本机服务 | LOCAL 模式拒绝一切转发头与非回环地址；配置不合规直接拒绝启动 |
| 大规模歌单耗时 | 体验差 | 限制单次上限、分批、进度与日志、可放弃预览 |

## 14. 验收清单

- [ ] 新注册音桥账号后能在 90 秒内完成一次 QQ → Apple 演示迁移。
- [ ] 交换方向后能完成 Apple → QQ 演示迁移。
- [ ] 演示音乐库能看到两次迁移创建的歌单。
- [ ] 匹配阶段不创建目标歌单；只有勾选确认后才写入，未勾选的匹配项计入「已跳过」。
- [ ] 真实 QQ 歌单链接可读取并预览。
- [ ] 粘贴真实 `media-user-token` 后能列出并读取本人 Apple 资料库歌单，迁到 QQ 音乐。
- [ ] 令牌为空或已失效时，真实 Apple 连接给出明确提示（不静默返回空歌单）。
- [ ] 未配置 Apple 开发者令牌时，迁入 Apple 被拒绝并提示改用 QQ 音乐 / 网易云作为目标（演示模式仍可迁入）。
- [ ] 迁移报告统计与逐首明细一致。
- [ ] 服务端日志不含 Cookie / Token 明文。
- [ ] 未登录访问 API 返回 401，介绍页与本地备份导入导出仍可用。
- [ ] 备份预览可选择已连接平台直接恢复：未登录时提示登录，未连接目标时打开连接弹窗，恢复报告与普通迁移一致且进入迁移历史。
- [ ] 备份超过 `max-tracks` 时明确提示只提交前 N 首，不静默丢弃。
- [ ] 其他音桥账号读取别人的任务返回 404；同账号其他会话只能只读查看。
- [ ] 服务重启后历史仍在，未确认的预览显示「任务已中断」，写入阶段中断的任务显示「结果待核查」。
- [ ] 历史报告中没有确认 / 重试入口，提交确认返回 409 并说明历史只读。
- [ ] 历史列表可按来源、目标、状态与日期区间筛选；非法筛选值返回 400，筛选结果仍只包含本账号的报告。
- [ ] 导出的摘要 CSV、逐首结果 CSV 与报告 JSON 与页面报告一致；时间按本地时区显示，可能触发表格公式的内容加单引号。
- [ ] 批量队列一次只跑一份：未连接目标平台时打开连接弹窗，队列方向锁定后不能中途更换，重复链接与超出 10 份的部分不会入队。
- [ ] 批量迁移的每一份都仍需人工确认才写入，完成后生成独立历史报告；「暂不迁移」只跳过该份并释放服务端预览，不影响其余队列。
- [ ] 失败或中断的队列项可「重新排队」，已完成的报告行保留在队列中以便导出批次小结。
- [ ] LOCAL 模式只监听 127.0.0.1；带转发头或伪造 Host 的请求被拒绝。
- [ ] PUBLIC 模式缺少 TLS、Secure Cookie、规范公网源或邀请码时启动失败。
- [ ] 缺少 CSRF 头的写请求返回 403；超大请求体返回 413；认证接口超频返回 429。
