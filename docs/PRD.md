# TuneBridge 音桥 · 产品需求文档（PRD）

> 2026 Qoder 高校创造力大赛 · LifeHack 生活娱乐赛道
> 版本：v1.1（MVP + 账号与历史）｜更新日期：2026-11-19

## 1. 一句话介绍

**TuneBridge 音桥**是一个浏览器里打开就能用的歌单搬运工具：登录本站音桥账号、在目标平台完成授权后，粘贴另一平台歌单链接，系统自动逐首搜索与匹配，由你勾选确认后写入目标平台，并把这份报告存进迁移历史。

## 2. 背景与问题

### 2.1 真实场景

- 小 A 一直是 QQ 音乐用户，最近买了 AirPods / HomePod，想转用 Apple Music，但 20 个自建歌单、上千首歌没有精力手动重建。
- 小 B 被 Apple Music 的编辑推荐吸引，却舍不得 QQ 音乐里多年积累的华语歌单，两个平台来回切换。
- 跨区、换手机、会员到期、朋友分享歌单……每一次平台迁移，都是一次重复劳动。

### 2.2 现有方案的问题

| 现有方式 | 问题 |
| --- | --- |
| 手动逐首搜索添加 | 一首歌约 20–30 秒，100 首歌要 40 分钟以上 |
| 截图 / 文本清单 | 只能「看」，不能恢复为可播放歌单 |
| 第三方爬虫脚本 | 要装环境、改代码，普通用户无法使用 |
| 平台官方迁移工具 | 只覆盖部分平台，且几乎不跨生态 |

### 2.3 机会

QQ 音乐与 Apple Music 分别代表国内曲库与全球生态，用户重叠度高、迁移诉求强，但两者之间没有官方互通工具。一个**无需安装、在浏览器完成授权、自动匹配、给出迁移报告**的小工具，可以实打实解决一个高频又烦人的问题。

## 3. 目标用户

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| 双平台学生党 | 手机 QQ 音乐、平板/电脑 Apple Music | 把歌单低成本搬过去 |
| 换生态用户 | 新购 iPhone / Mac / HomePod | 保留多年收藏 |
| 歌单创作者 | 在两个平台同步运营歌单 | 一次编辑、两边同步 |
| 好奇体验者 | 比赛评委、朋友 | 不登录也能 30 秒看到完整效果 |

## 4. 产品目标与非目标

### 4.1 MVP 目标

1. 用户可以在浏览器中完成 **QQ 音乐 → Apple Music** 与 **Apple Music → QQ 音乐** 两个方向的歌单迁移。
2. 目标平台授权流程清晰，来源歌单链接粘贴后能立即预览。
3. 自动匹配歌曲，**由用户勾选确认后才创建目标歌单并写入**，输出成功 / 未匹配 / 已跳过的逐首结果。
4. 无平台账号、无开发者凭据的用户可以通过**演示模式**完整体验整个流程（只需注册一个本站音桥账号）。
5. 全流程不持久化任何音乐平台凭据，服务端不记录 Cookie / Token；落盘的只有音桥账号与迁移报告快照。
6. 迁移结果与历史可以在服务重启后查看，但历史只读，绝不自动继续或重试写入。

### 4.2 非目标（本期不做）

- 不迁移「我喜欢」、专辑、本地文件、播放记录。
- 不做歌单持续双向同步（仅一次性复制）。
- 不做音频下载、播放、版权绕过。
- 不覆盖 Spotify 等更多平台（网易云已作为目标平台试用接入，架构继续预留）。
- 不做后台管理、运营面板、找回密码、邮件验证与多实例共享会话。
- 不做跨设备同步或云端账号（音桥账号只存在于部署实例本地的 H2 文件中）。
- 不做自动断点续传与自动重试：写入结果不确定时一律交给人工核查。

## 5. 核心用户流程

```
注册 / 登录音桥账号（本站账号，不是音乐平台账号）
   ↓
选择方向 A → B
   ↓
授权登录目标平台 B（QQ Cookie 连接 / Apple MusicKit 授权 / 演示账号）
   ↓
粘贴来源平台 A 的歌单分享链接
   ↓
解析并预览歌单（封面、名称、曲目数、前几首）
   ↓
点击「开始匹配」→ 读取 A 歌单 → 逐首在 B 搜索匹配（此时不写入任何平台）
   ↓
审阅逐首结果，勾选要带走的歌曲 → 点击「确认迁移」
   ↓
创建 B 歌单 → 按来源顺序批量写入所选歌曲
   ↓
迁移报告：成功 N 首 / 未匹配 M 首 / 已跳过 K 首 / 目标歌单入口（报告存入迁移历史）
```

### 5.1 关键交互原则

- **三步之内开始**：方向、授权、链接，主按钮始终只有一个。
- **每一步都有反馈**：连接状态、解析 loading、迁移进度、逐首结果。
- **匹配与写入分离**：匹配阶段只读；只有明确勾选确认才会创建歌单和写入，未确认的预览过期后自动失效。
- **失败可解释**：未配置 Apple 开发者令牌、Cookie 失效、QQ 写接口受限，都给出人话提示与替代方案。
- **结果不确定时不重试**：写入中断或任务在写入阶段被重启，报告标注「结果待核查」，引导用户去目标平台确认，产品绝不自动重试。
- **演示优先**：评委只需注册一个音桥账号，即可一键进入演示并跑通双向迁移。

## 6. 功能需求

### 6.1 P0（MVP 必须）

| 编号 | 功能 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| F1 | 平台方向切换 | QQ ↔ Apple 双向切换，可一键交换 | 切换后授权区、链接示例、提示文案同步更新 |
| F2 | 演示授权 | 无需凭据连接演示账号，使用内置曲库 | 点击即连接，状态变为「演示模式」 |
| F3 | QQ 真实连接 | 粘贴 y.qq.com Cookie，服务端解析 uin 与票据 | 连接成功后显示脱敏账号；无效 Cookie 返回明确错误 |
| F4 | Apple 真实连接 | 配置开发者令牌时，浏览器内 MusicKit JS 授权；否则可粘贴 Music-User-Token | 获取 token 后服务端校验并显示已连接 |
| F5 | 歌单链接解析 | 支持 QQ 歌单链接/ID、Apple 歌单链接/ID、演示链接 | 非法链接被拒绝且提示格式 |
| F6 | 歌单预览 | 展示封面、名称、作者、曲目数与曲目列表 | 预览数据与实际迁移读取一致 |
| F7 | 自动迁移 | 后台任务读取、匹配、创建、写入，前端轮询进度 | 两个方向均可完成；进度与日志实时更新 |
| F8 | 匹配报告 | 逐首展示匹配结果、目标歌曲、相似度、未匹配原因 | 报告可滚动查看，统计数字准确 |
| F9 | 演示音乐库 | 演示模式下展示本次会话创建的歌单，可再次作为来源 | 迁移完成后可在目标演示库中看到新歌单 |
| F10 | 会话级凭据 | 凭据仅存于服务端会话内存，断开连接即清除 | 重启服务或断开连接后不可用；日志无明文凭据 |
| F11 | 歌单备份与恢复 | 读取 QQ 歌单、粘贴曲目或导入 CSV/JSON，在浏览器预览并导出；也可选择已连接平台，把预览曲目作为来源恢复成新歌单 | 预览、导出与恢复共用同一份曲目数据；恢复不要求来源平台已连接，输出逐首报告 |
| F12 | 音桥账号 | 本站账号注册 / 登录 / 退出，本机模式免邀请码，公网模式需邀请码 | 用户名规范化、弱密码与重名被拒；登录失败提示不泄露账号是否存在 |
| F13 | 账号隔离 | 连接、任务、历史归属音桥账号 | 其他账号读取返回 404；同账号其他会话只读，不能确认或放弃 |
| F14 | 任务持久化与迁移历史 | 每个状态变更保存报告快照，历史分页可查、只读 | 服务重启后历史仍在；未确认预览标记为已中断；历史中无法提交确认 |
| F15 | 部署边界 | LOCAL 只监听回环、拒绝转发头；PUBLIC 要求 TLS、Secure Cookie、规范源与邀请码 | 配置不合规直接拒绝启动；伪造 Host / 跨站写请求返回 403 |
| F16 | 请求防护 | 会话 CSRF 头、登录换会话 ID、认证限流、请求体上限 | 缺少 CSRF 返回 403；超频返回 429；超大请求体返回 413 |

## 7. 页面与信息架构

单页应用，七个区域：

1. **首屏 Hero**：品牌、价值主张、核心 CTA、能力标签。
2. **迁移工作台**：
   - 方向选择（A → B，交换按钮）；
   - 来源连接卡与目标连接卡；
   - 来源链接输入 + 解析预览；
   - 匹配按钮、勾选确认区与说明。
3. **进度浮层**：步骤时间线、进度条、实时日志、当前曲目。
4. **结果页 / 弹层**：统计卡、逐首报告、目标歌单入口、演示音乐库入口。
5. **备份与恢复**：歌单链接读取、手动粘贴、CSV/JSON 导入，预览后导出或选择目标平台恢复迁移。
6. **音桥账号弹窗**：登录 / 注册切换、邀请码字段（公网模式）、当前账号摘要、退出入口。
7. **迁移历史弹层**：本账号的只读报告分页列表，进入单份报告查看逐首明细与恢复提示。

### 7.1 连接弹窗

- 演示授权（推荐给评委）：一键连接。
- 真实授权：
  - QQ：Cookie 文本框 + 获取方式说明 + 安全提示；
  - Apple：MusicKit 授权按钮（服务端已配置开发者令牌时）或 Music-User-Token 文本框 + 说明；
  - 网易云：本机配对码（仅 LOCAL 部署可用）。
- 「如何在浏览器获取 Cookie」提供折叠说明。

### 7.2 未登录与失效状态

- 介绍页、本地粘贴曲目与 CSV / JSON 导入导出无需登录即可使用。
- 平台读取、连接、演示匹配与历史需要登录；未登录触发时打开账号弹窗并提示「登录后请重新点击操作」，不会自动重放刚才的操作。
- 登录失效（401）时清空页面私有数据并提示重新登录，已开始的写入不会被撤销，引导先查历史与目标平台。

## 8. 演示模式设计

演示模式不是假按钮，而是**一套内置曲库与内存音乐库**：

- 内置 QQ 风格歌单 12 首、Apple 风格歌单 10 首，包含 1–2 首对方曲库没有的歌，用于展示未匹配。
- 迁移时真实执行匹配算法、歌单创建、批量写入与结果统计，只是数据落在内存。
- 每次迁移创建的歌单进入「演示音乐库」，可继续作为下一次迁移的来源，支持 QQ → Apple → QQ 往返。
- 演示账号连接与演示音乐库绑定音桥账号的浏览器会话，退出登录后失效；迁移报告仍会存入该账号的历史。
- 页面明确标注「演示模式」，避免用户误以为操作了真实账号。

## 9. 成功指标

| 指标 | 目标 |
| --- | --- |
| 首次访问到完成演示迁移 | ≤ 90 秒（含注册登录） |
| 演示迁移匹配率（真实曲库交集） | ≥ 80% |

| 服务重启后历史可读 | 100%，且不产生任何自动写入 |

## 10. 数据、隐私与合规

- **最小化**：只读取歌单公开信息与曲目元数据（歌名、歌手、专辑、时长、封面）。
- **不持久化平台凭据**：Cookie、Music-User-Token、开发者令牌不写入数据库、不写日志、不落盘、不返回前端。
- **持久化范围**：数据库只保存音桥用户名、PBKDF2 密码哈希，以及迁移报告快照（方向、曲目元数据、匹配结果、统计与日志）。网易云 CLI 的本机登录态由 CLI 自行管理，属于本机数据。
- **账号隔离**：连接与活动任务绑定浏览器会话并归属音桥账号；历史按账号查询，跨账号读取返回 404，同账号其他会话只读。
- **透明**：真实授权页明确说明数据用途；演示模式明确标注；历史弹窗说明「只读、不保存平台凭据、重启不自动重试」。
- **合规边界**：仅用于用户本人歌单备份迁移，不提供下载、破解、绕过版权或批量抓取能力；遵循平台服务条款，接口变化时降级到演示模式并提示。
- **风险提示**：QQ 音乐写接口可能触发风控或需要签名通道，产品会如实报告失败，不伪造成功。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| QQ 写歌单接口风控 / 变更 | 真实迁移失败 | 逐层校验业务码；失败给出原因；演示模式兜底；文档标注 |
| Apple 开发者令牌 / 订阅门槛 | 无法真实连接 | 支持静态令牌或 `.p8` 自动签发；未配置时明确提示 |
| 第三方 API 不稳定 | 读取超时 | 超时 + 有限重试；错误可读；不静默返回空歌单 |
| 歌曲版本差异 | 匹配错误 | 标题 + 歌手 + 专辑综合打分，展示匹配依据，低置信默认不勾选 |
| 凭据泄漏 | 账号安全 | 平台凭据仅会话内存、日志脱敏、断开即清除、PUBLIC 模式强制 HTTPS |
| 历史快照与目标平台不一致 | 用户误判迁移结果 | 报告标注写入数与「待核查」提示；历史只读、禁止重新提交 |
| 重启导致任务状态错乱 | 重复写入或误认为成功 | 状态快照持久化，启动时把未结束任务标记为已中断，不自动恢复执行 |
| 公网部署被批量注册或撞库 | 账号与资源风险 | 邀请码注册、按来源与全局窗口限流、密码长度下限、失败提示不泄露账号存在性 |
| 反向代理伪造来源 | 越权访问本机服务 | LOCAL 模式拒绝一切转发头与非回环地址；配置不合规直接拒绝启动 |
| 大规模歌单耗时 | 体验差 | 限制单次上限、分批、进度与日志、可放弃预览 |
